# CLAUDE.md — streaminfo-sitebot

Контекст для Claude Code и любого нового чата, который откроет этот репозиторий.

## Что это

Сборщик состояния беларуских Twitch-стримеров для раздела `mashninski.com/strymy`.
Раз в 10 минут спрашивает Twitch, кто в эфире, ловит момент окончания стрима, ищет запись
и пишет `data/twitch-state.json`. Сайт читает этот файл по raw-ссылке и от его изменений
не пересобирается.

Полная спека и план — в **приватном репозитории сайта** `mashninski-site`
(локально `D:\production\mashninski-site`): `claude/twitch-spec.md` — как устроено,
`claude/twitch-plan.md` — что делать и сколько стоит. Хронология решений —
`claude/journal.md` там же. В проекте claude.ai этих документов больше нет.

Своего журнала у этого репозитория нет и заводить его не надо: продуктовые решения
по боту живут в журнале сайта, здесь — только устройство кода.

## Раскладка

```
streamers.json                  реестр: кого показываем, соцсети, заметки — правится руками
collect.py                      сборщик, единственный исполняемый файл
data/twitch-state.json          состояние, пишет только бот, руками не трогать
data/twitch-stats.json          статистика для вкладки «Агляд» (была «Агульная статыстыка»), тоже только бот
data/archive/YYYY-MM.json       архив месяца для вкладки «Хронікі», тоже только бот
.github/workflows/collect.yml   cron */10
```

## Запуск

```bash
pip install requests
export TWITCH_CLIENT_ID=... TWITCH_CLIENT_SECRET=...
python collect.py
```

`FORCE_VOD_CHECK=1` — проверить записи вне расписания.

## Устройство, если правишь код

- **Онлайн-статус здесь не хранится.** В `twitch-state.json` лежат переходы: начало и конец
  сессии. Живой статус сайт берёт своей функцией напрямую у Twitch. Не добавляй сюда поле
  «сейчас онлайн» как источник правды для фронта — оно протухнет между прогонами.
- **Коммит только при изменениях.** Сравнение идёт по ветке `streamers` состояния; `updated_at`
  в сравнение не входит намеренно. Любое поле, которое меняется каждый прогон само по себе
  (метки времени проверок, счётчики), порождает коммит каждые 10 минут — так уже было
  с `vod.seen_at` и со счётчиком `missing_runs`, оба починены. Добавляя поле, проверь это.
- **Расписание проверки VOD определяется часами, а не файлом состояния** (`ts.minute < 10`).
  Хранить «когда проверяли в последний раз» в файле нельзя по причине выше.
- **`started_at` берётся из ответа Twitch, `ended_at` — по времени прогона.** Поэтому ошибка
  есть только у конца сессии, и длительность врёт максимум на интервал опроса.
- **Длительность из VOD точнее наблюдаемой.** Когда запись находится по `stream_id`,
  `duration_min` и `ended_at` пересчитываются по ней, `source` становится `vod`.
- **`Get Videos` принимает только один `user_id` за запрос** — отсюда отдельный вызов
  на стримера. `Get Users` и `Get Streams` принимают до 100 за раз.
- **VOD живёт 7–60 дней** в зависимости от типа канала и подписки Prime/Turbo. Срок не
  вычисляем, а проверяем фактическим наличием записи; пропала — ставим `vod.gone = true`.
- **`stale: true`** — Twitch не отдаёт канал шесть прогонов подряд: бан, удаление или смена
  логина. Такие карточки на сайте прячутся.
- **Смена `stream_id` без офлайна — рестарт, а не продолжение.** Прошлая сессия закрывается
  концом не позже начала новой, иначе часы суток задвоятся.

### Статистика (`data/twitch-stats.json`)

Спека — `claude/twitch-stats-spec.md` в репозитории сайта. Что важно в коде:

- **`in_progress` копит секунды, не минуты.** В минуты переводится один раз при закрытии
  сессии — округление на каждом прогоне набегало бы. Время от начала эфира до первого
  прогона, который его увидел, тоже засчитывается: иначе часы не сходятся с `duration_min`.
- **Месяцы и часы суток — по Мінску** (UTC+3 круглый год, фиксированное смещение).
  Сессия через полночь 1-го числа целиком уходит в месяц начала.
- **`followers.changed_at` — когда число изменилось, а не когда проверяли.** Отметка
  проверки менялась бы каждый прогон — то же правило, что с `vod.seen_at`.
- **Подписчики — внутренний GraphQL Twitch**, один запрос на всех, три попытки. При сбое
  старое число не трогается, `fail_runs` растёт до шести и останавливается; с шестого
  в логе строка `ПОДПІСЧЫКІ НЕ СОБІРАЮЦЦА ЎЖО ГАДЗІНУ`. Client-Id там — публичный
  идентификатор веб-клиента twitch.tv, не секрет; переопределяется `TWITCH_GQL_CLIENT_ID`.
- **`prev_broadcast_at` в состоянии — начало последнего эфира до первой сессии `history`**,
  тем же GraphQL-запросом (`lastBroadcast.startedAt`). По нему сайт считает перерыв перед
  первой известной сессией точно, а не «больш за» от `added_at` (спека статистики, §9,
  «Точное число»). Не «последний эфир вообще»: после эфира-возвращения Twitch отдаёт уже
  его, и прошлая дата затёрлась бы. Поэтому берётся, только когда канал не в эфире (и по
  Helix, и по `stream` в ответе) и эфир раньше первой сессии `history` больше чем на час;
  пока `history` пуста — любой. Дальше поле не меняется, коммитов не порождает. Сбой
  запроса значение не трогает.
- **`collecting_since` пишется один раз.** Не сбрасывать: по нему сайт отличает
  «не стримил» от «бот ещё не собирал».
- **Массивы чисел пишутся в одну строку** — иначе `hours` занимал бы 24 строки на каждый.

### Архив месяцев (`data/archive/YYYY-MM.json`)

Спека — `claude/twitch-chronicle-spec.md`, §4, в репозитории сайта. Каждый прогон
`update_archive` пересобирает файлы текущего и прошлого месяца из статистики и состояния,
без запросов к Twitch, и пишет только при разнице (без `updated_at`). Месяц ушёл из
`monthly` — файл больше не трогается, он заморожен сам. Что важно в коде:

- **Файл собирается поверх своей прошлой версии.** `recent_sessions` держит 31 день,
  `history` — 20 сессий, а месяцу нужны все сессии: они копятся в самом файле, ключ —
  `started_at`. Поэтому файл архива руками не правится и не удаляется — сессии старше
  31 дня взять больше неоткуда.
- **Источник сессий — `recent_sessions`, не `history`.** Только эти сессии учтены
  в `monthly`, и `launches` равно числу сессий в файле. `duration_min` считается
  по формуле `session_from_live`, а не берётся из `history` (там её уточняет VOD):
  иначе сумма по сессиям разошлась бы с `minutes`.
- **`prev_ended_at` — из `history`, а найденное раньше остаётся кандидатом:** к концу
  месяца нужная сессия могла уйти из 20 последних.
- **`prev_broadcast_at` — только когда `prev_ended_at` null:** начало прошлого эфира
  по Twitch из состояния, отдельным полем — это начало, а не конец. Из состояния берётся,
  пока `history` короче 20 сессий; найденное раньше остаётся.
- **Обновляются только стримеры, которых бот собирает сейчас.** Убранный из реестра
  или скрытый остаётся в файле таким, каким был, — в своём месяце человек не пропадает.
  При смене логина запись переезжает на новый логин, а не двоится.
- **Сбой архива не мешает состоянию и статистике** — они уже записаны, — но идёт
  в письмо автору через `alert`: сессии месяца живут в `recent_sessions` только 31 день.

## Чего не делать

- Не клади сюда ключи. `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` — только GitHub Secrets.
- Не делай репозиторий приватным: на приватном опрос раз в 10 минут выходит за бесплатные
  2000 минут Actions и начинает стоить около $14/мес.
- Не подключай базу данных. Вся архитектура держится на том, что состояние — файл в git.
- Не правь `data/twitch-state.json` руками: следующий прогон перезапишет.
- Не заводи здесь `claude/` с журналом и спеками — они в репозитории сайта.
